# 招聘 Agent G1b 产品规格实施计划

> 状态：已完成  
> 日期：2026-08-10  
> 范围：把 G1a 的“单轮可信完成件”串成当前、完整、可失效的多轮终面评估包，并形成下一轮面前追问简报；不接真实系统、不产生招聘决定。

## Goal

形成可评审、可验收的 G1b 产品规格，使产品、招聘运营、用人部门、研发、AI/数据、QA 与隐私法务能够对以下结果达成同一理解：当前必需轮次完成或被有效豁免后，系统自动编译一个只引用当前已确认评价和人类决定、显式展示缺项/冲突/豁免、输入变化即失效的终面评估包，并将权威审阅任务摆到最终招聘决策人桌面；任何 Agent 都不能在其中生成录用/淘汰建议。

## Approach

1. 先冻结领域词：必需轮次、轮次完成件、轮次豁免、面前追问简报、跨轮问题、终面评估包版本、终面评估就绪与包失效。
2. 记录两项难以逆转且容易被误解的产品决策：终面包是不可变编译物而非实时拼接页面；下一轮面试官先看到证据缺口和建议问题，不先看到前轮总分/决定。
3. G1b PRD 只覆盖 G1a 完成件之后到 `FINAL_ASSESSMENT_READY`：轮次依赖、自动激活、追问简报、输入清单、去重、缺项/冲突/豁免、编译/发布/失效和最终审阅任务。
4. 将新命令、事件和不变量写回现有领域规格，维持 Case 六阶段、Round 子状态和 RuntimeEnvelope 正交。
5. 为全部 FR/AT 建立测试与证据槽；产品规格覆盖不能冒充工程实现或真人验证。

## Risks / Unknowns

- 试点岗位的实际轮次图、必需/可选轮次、并行面试、豁免权限和最终决策人尚未冻结；PRD 只能给默认模型，不能替业务签字。
- “跨轮冲突”若定义过宽，会把正常的情境差异误判为问题；Agent 只能提出问题候选，不能替人裁决哪一轮正确。
- 面前简报既要提高追问效率，也可能造成锚定和敏感信息扩散；默认采用分阶段披露，具体字段仍需隐私/公平评审。
- 轮次评价更新、决定纠正、证据删除和评分卡迁移都可能使终面包失效；跨聚合传播延迟必须在工程阶段用读取前重验和事件补偿解决。
- 当前原型只证明一条两轮正常链可到 `FINAL_ASSESSMENT_READY`，没有证明冲突、豁免、失效、旧链接或通知故障。
- 当前无实现仓库、团队、真人样本或业务签核；所有新产物最多进入 `SPEC`。
