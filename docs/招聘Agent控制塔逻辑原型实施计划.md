# 招聘 Agent 控制塔逻辑原型实施计划

日期：2026-08-10  
状态：已完成  
产物性质：可抛弃的单文件逻辑原型，不是生产前端

## 目标

交付一个无需安装、可双击运行的单文件 HTML，让产品、招聘运营、技术和用人部门能够亲手推动一份合成申请从简历投递走到终面材料就绪，并验证异常、暂停、撤回、幂等与强制人审是否符合领域规格。

验收结果不是“界面看起来完整”，而是非研发人员能够回答：现在走到哪一步、为什么停住、谁必须决定、Agent 可以做什么、什么动作必须被拒绝、处理异常后回到哪里。

## 方案

- 采用单文件 HTML/CSS/JavaScript，不使用框架、服务端、数据库或外部接口。
- 将领域逻辑放在纯 reducer/state-machine 模块中；DOM 只负责渲染与派发动作。
- 同时提供自由操作区和可重放的引导场景。
- 使用完全合成的候选人、岗位、会议和事件数据，不读取真实简历或录音。
- 案件阶段、轮次状态、运行态和暂停轴分别展示；页面标签由它们推导，不形成第四套可写状态。
- 所有非法动作返回可读拒绝原因，不通过隐藏按钮掩盖状态约束。

选择逻辑原型而不是部署型网站，因为这轮要回答状态模型是否成立；不验证视觉品牌、正式前端架构、连接器或持久化。

## 文件级步骤

1. 新建 `招聘Agent控制塔_逻辑原型.html`：写明验证问题、非生产声明、合成数据说明和使用方式。
2. 在同一文件中实现纯状态模块：初始状态、领域动作、合法迁移、幂等记录、异常包、事件时间线和页面投影函数。
3. 增加完整状态面板：简历投递、申请案件、当前轮次、运行/暂停、下一动作、人审点、异常与最近变化。
4. 增加自由操作按钮：覆盖 G2 前链、G1a 面后闭环、G1b 终面包以及暂停、撤回、重复事件和恢复。
5. 增加引导场景：正常全链、路由冲突、录制不同意、重复事件、确认/决定分离、暂停恢复、候选人撤回。
6. 更新 `招聘Agent推进看板.md`：把“可点击控制塔原型”标记为已证实的设计验证产物，同时继续保持工程研发和真实发布未开始。
7. 更新本计划为已完成，并记录原型回答了什么、仍未回答什么。

## 风险与未知

- 原型只验证状态和交互语义，不能证明连接器、权限、模型质量、合规或生产可靠性。
- 领域专家尚未实际点击并提出异议，因此“模型成立”只能写成待评审，不写成已验证。
- 为展示完整终局，原型会覆盖 G1a/G1b/G2，但这不改变工程仍按阶段放行的路线。
- 浏览器内存刷新即重置是刻意设计，不代表正式产品的数据策略。

## 验证

- HTML 可直接打开，无网络依赖，无真实数据和外部请求。
- JavaScript 语法检查通过，HTML 结构检查无阻断错误。
- 每个引导场景可从确定初态重复执行，并显示完整当前状态和最近变化。
- 重复事件不重复产生业务效果；非法迁移给出拒绝原因。
- 没有人工部门决定不能进入面试，没有面试官确认不能完成轮次，没有人工最终决定不会关闭案件。
- 暂停和撤回优先于队列动作；异常恢复回到原业务阶段而不是新建孤儿案件。
- 推进看板明确区分“原型已完成”“工程未实现”“真人试点未放行”。
