# 申请案件是招聘中段的业务主线

流程以“租户 × 候选人 × 岗位需求 × 招聘周期”的申请案件为聚合根，而不是以手机号、邮箱或候选人 ID 直接贯穿。候选人可能同时申请多个岗位、跨周期再次申请或发生身份合并；用申请案件承载状态、SLA、画像版本、面试轮次和决定，可以避免跨岗位串档，同时保留候选人层面的身份与权利请求。

邮件、ATS 回调或上传材料先进入 `ResumeSubmission`。在人、岗位需求和招聘周期尚未唯一解析时，只能停留在投递路由或人工复核，不能创建缺少业务键的“半个申请案件”。

## Considered Options

- 候选人作为流程主线：模型简单，但无法正确隔离多岗位和多周期。
- ATS 记录作为流程主线：依赖具体客户数据模型，不利于内部试点和跨系统托管。
- 申请案件作为流程主线：多一个业务对象，但边界稳定且可跨连接器。

## Consequences

- 同一候选人可拥有多个相互隔离的申请案件。
- 手机号和邮箱只作为身份解析信号，不是业务主键。
- 转发邮件、重复附件和 ATS 重复回调先在简历投递层去重；唯一路由后才允许开案。
- 删除、更正和合并需要同时处理候选人身份与其关联案件，但不能把案件历史相互覆盖。
