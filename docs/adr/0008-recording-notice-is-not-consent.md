# 录制告知不等于采集授权，面试与采集彼此分离

会议邀请中的录制告知只证明告知已送达，不能产生参与人的采集选择凭证或让采集闸门通过；面试开始与音视频采集是两个动作，采集必须按当前在场参与人、目的、告知与选择版本以及处理控制事实持续重验。我们接受无录制路线可能降低自动转写覆盖率，以保证拒绝或撤回采集不会剥夺候选人的面试机会，也不会成为评价信号。

## Considered Options

- 把接受会议邀请视为默示同意：步骤少，但选择不显著、不可逐目的证明，也无法处理转发和晚加入者。
- 排期时一次性取得选择：比默示同意清楚，但会在参与人或用途变化后失真。
- 以会话参与人和目的为单位持续计算采集闸门：实现更复杂，但能处理拒绝、撤回、晚加入和限制处理。

## Consequences

- `StartInterview` 不得隐式触发 `RequestCaptureStart`；开始/停止请求与平台确认分离，只有当前回执或可信对账能把采集标为 `ON` 或 `STOPPED`。无录制路线仍可正常进入面试和人工评价。
- 晚加入者不继承他人选择；其状态未解决时必须暂停采集或保持无录制。
- 会中撤回或适用范围内的处理限制生效后立即隔离新处理并发出安全停止请求；平台未确认前不得声称已停止，并按数据血缘处置已有材料。
- 若会议连接器不能可靠停止采集或处理晚加入者，试点不得开放录制类自主动作。
