# 招聘 Agent G2 产品规格实施计划

> 日期：2026-08-10  
> 状态：已完成  
> 范围：简历投递进入受控收件源 → 合法进入首轮面试并向 G1 交接

## Goal

把 G2 定义成一条无需 HR 手动发起、但保留候选人选择权和人类招聘决定权的案件链：接收并去重简历投递，完成身份/岗位/周期唯一路由，生成有证据的人岗匹配材料，向用人部门发起并追踪人工决定，在决定进入面试后完成候选人协调、日历/会议预定、录制或无录制路线选择、开场采集闸门，并把合法发生的面试会话交给 G1a/G1b。

本计划交付产品和控制规格，不声称工程实现、连接器可用、真实数据合规或业务效果已经通过。

## Approach

1. 沿用一个案件主线：`ResumeSubmission` 先于 `ApplicationCase`；只有唯一路由后才开案。
2. 沿用六个案件顶层阶段；排期和会面进展属于 `InterviewRound` / `InterviewSession`，不新增页面状态真相源。
3. 将“提议时段”和“外部预定成功”分离，所有日历/会议写入经确定性 `ActionExecution`、版本重验、幂等和回执后才提交业务事实。
4. 将录制告知、参与人选择和实际采集分离；没有当前有效、逐目的、可证明的授权时只能走等价无录制路线或阻断采集，不能阻断面试本身。
5. 低匹配分数、模型材料和催办都不拥有招聘决定；部门邀请/拒绝和轮次决定只能由有权限的人提交。
6. 以 FR/AT 追踪矩阵和文档 lint 锁住产品边界，再进入工程契约拆分；规格通过不替代真实 Gate 证据。

## Risks

- 路由不唯一却过早开案会造成跨岗位串档；必须在投递层停住并生成可决策异常包。
- 历史通过结果和姓名、学校、口音、空窗等代理变量会放大偏差；禁用字段、证据规则、分层评测和所有市场发布审计都必须前置。
- 候选人选中时段后，日历冲突或旧回调仍可能发生；预约修订、执行前重验和外部对账必须共同阻止双重预定。
- 在邀请中放入录制条款不能证明授权；晚加入者、撤回、用途变化和无录制路线必须进入运行门，而不是只写文案。
- “全程无需 HR 触发”容易被误读为无人决策；规格必须区分自动推进、人类业务决定和计划外 HR 搬运。
- 文档覆盖完整仍可能掩盖连接器、身份权限、真实数据和业务采用缺口；看板和 Gate 必须持续使用证据状态而非完成百分比。

- 在验收记录中分别列出“产品规格已验证”和“工程/集成/合规/真实业务尚未验证”。
