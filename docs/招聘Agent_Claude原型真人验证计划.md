# 招聘 Agent：Claude 原型真人验证计划

版本：v0.1
日期：2026-08-10
状态：待原型返回后执行
适用范围：G3 画像治理交互真人门

## 1. 目的与判定边界

本计划用于在 Claude 高保真可点击原型返回后，验证七类 G3 HUMAN 是否能够：

1. 理解自己当前需要完成的任务、依据、后果和截止时间；
2. 区分 Agent 准备、画像提案、双人批准、独立发布授权、控制面发布准备、发布记录、下游同步和当前生效；
3. 在正常链和高风险分支中选择正确、安全且符合职责边界的动作；
4. 在刷新、超时、旧版本、重复提交、部分成功、暂停和接管后找到权威状态与恢复入口；
5. 使用键盘、读屏、200% 缩放和 reduced motion 完成关键任务。

真人门通过仅表示：**G3 原型的角色任务、状态表达、风险处理和恢复交互具备进入工程评审的证据**。

真人门不证明以下事项：

- 服务端角色权限、深链拒绝、租户隔离或字段级访问控制已经实现；
- 命令、外部动作和回调在真实系统中具备幂等性；
- 邮箱、IM、日历、会议、ATS 或画像下游连接器可靠可用；
- 真实结果数据来源合法、统计或公平结论有效；
- Agent harness、A0/A1/A2、真实发布、暂停使用或生产回滚已实现；
- 候选人、面试官、最终招聘决策人等招聘中段其他角色的体验已经通过验证。

因此，即使本计划全部通过，也**不解除项目总 Gate 的 No-go**。服务端权限、幂等、真实数据、连接器、工程行为与生产恢复必须由后续独立证据证明。

## 2. 研究原则

- **任务验证，不做偏好投票**：以是否完成任务、是否理解事实和是否进入安全终态为主，不以“喜欢”“高级”“好看”代替证据。
- **Teach-back，不靠猜测意图**：参与者必须用自己的话说明当前事实、下一责任人、动作后果和是否已影响招聘。
- **风险注入，不只播放页面**：每个危险分支必须由参与者实际判断、选择动作并完成恢复。
- **版本不可变**：研究中的原型构建和合成数据 fixture 必须有版本与哈希；不得在同一版本下静默修改。
- **角色真实**：核心样本必须真实承担对应职责，不能用产品、设计或相邻岗位代理。
- **完全合成数据**：原型、录屏、截图与研究记录不得出现真实候选人、员工或客户个人信息。
- **不把不可测项判为通过**：原型无法证明的服务端行为记为 `NOT_TESTABLE`，不能用按钮隐藏或模拟成功代替。

## 3. 招募方案

### 3.1 核心完成样本

七类角色各完成 2 人，共 14 人：

| 角色 | 完成样本 | 参与条件 |
|---|---:|---|
| 用人负责人（Hiring Owner） | 2 | 最近 12 个月实际参与岗位画像或招聘标准决定 |
| HRBP / 画像治理负责人（Profile Governance） | 2 | 实际参与画像治理、规则评审或独立会签 |
| 发布授权人（Publication Authorizer） | 2 | 实际承担发布、变更或高风险配置授权职责 |
| 结果数据管理员（Data Steward） | 2 | 实际处理结果口径、来源冲突、纠正或数据质量 |
| 隐私 / 公平负责人（Privacy/Fairness） | 2 | 实际承担隐私、合规、公平或风险评审职责 |
| AI / 数据分析师（Analyst） | 2 | 实际负责样本、评测、实验或因果边界审查 |
| 招聘运营 | 2 | 实际处理招聘 SLA、异常、系统对账或人工接管 |

每个角色尽量包含一名熟练使用者和一名相对新手，并优先来自两个不同业务单元或招聘场景。排除本项目规格作者、原型设计者和已参加内部试跑的人。

### 3.2 候补与无障碍样本

- 每个角色建立 1 名候补，不计入完成样本；用于爽约替补或修复后的独立复测。
- 至少包含 2 名真实辅助技术用户，可与 14 名核心样本重叠。
- 若无法重叠，则额外完成 2 场无障碍任务，完成样本总数为 16。
- 无障碍测试者不能替代缺失的角色样本；角色任务与辅助技术证据分别统计。

## 4. 两套合成 Fixture

所有参与者使用同一字段口径，但不得共用会造成学习泄漏的答案提示。每套 fixture 必须保存 `fixture_id`、版本、内容哈希、起始状态和预期安全终态。

### Fixture A：正常治理与仅未来招聘发布

- 当前画像 `v4`，候选画像 `v5`；
- 结果来源已批准且基本一致，成熟标签和完整分母满足研究前提；
- 研究计划、候选修订和分析分区已先冻结，独立测试样本尚未提前打开；
- 当前版与候选版差异、反证、未知、重要人群区间和回滚目标均可查看；
- 作用范围仅为指定岗位的未来招聘，在途案件保持原钉住版本；
- 用于组成一条完整正常链接力和验证角色间独立任务。

### Fixture B：更正、风险阻断与部分同步恢复

- 当前画像 `v7`，候选画像 `v8`；
- 包含后来更正的结果来源、缺失/删失样本、潜在代理变量和不可比分组；
- 包含旧批准任务、重复提交、过期发布授权和权限变化；
- 包含发布记录已创建但部分下游仍使用旧版本的状态；
- 包含暂停使用与迟到发布竞态，以及仅能回到仍允许的上一安全版本；
- 用于组成第二条完整链接力和覆盖八个危险分支。

两套 fixture 都必须为每个角色提供最小必要信息；不得为了方便研究而向普通角色暴露保护属性、内部风险码、事件名、哈希或完整工程日志。

## 5. 研究形式与正常链

### 5.1 单场结构

每场预计 60 分钟：

1. 研究同意、角色背景与辅助需求：5 分钟；
2. 无提示首屏理解：5 分钟；
3. 本角色正常链任务：20 分钟；
4. 两个高风险分支和至少一个恢复演练：20 分钟；
5. 关键状态 teach-back：5 分钟；
6. 复盘与信心评分：5 分钟。

主持人可以澄清业务情境，但不能指示按钮位置、正确选项或状态含义。任何操作提示都必须记录为干预，并使该任务不再计为 `UNASSISTED_PASS`。

### 5.2 两次独立正常链接力

Fixture A 与 Fixture B 各执行一次完整链接力：

> Data Steward → Analyst → Privacy/Fairness → Hiring Owner → Profile Governance → Publication Authorizer → 招聘运营

每个角色从前一角色完成后的版本化快照开始，并必须确认：

- 当前事实与上一步发生了什么；
- 自己可以看到什么、不能看到什么；
- 当前唯一主要动作及其业务后果；
- 下一责任人是谁；
- 当前是否已经影响未来招聘或在途案件。

若可点击原型不能跨账号持久化，可使用事先冻结的连续状态快照模拟接力，但必须记录每个快照的输入版本和预期输出。该模拟只能证明交互理解，不能证明真实状态提交或幂等。

## 6. 七角色关键任务

| 角色 | 正常链任务 | 必须完成的判断 | 禁止动作验证 |
|---|---|---|---|
| Data Steward | 对账多来源结果，判断成熟、未知、缺失或删失，并处理后来更正 | 缺失不等于失败；更正会使旧派生物和旧任务失效 | 不评价候选人、不批准提案、不授权或发布画像 |
| Analyst | 核对完整分母、选择机制、固定分区、预登记和“候选先锁定再开独立测试样本” | 偷看、小样本、宽区间、重要人群退化或不可比合并时不得形成发布型提案 | 不批准、授权、发布或回滚画像 |
| Privacy/Fairness | 审查用途、重要人群伤害、代理风险、删除/限制状态和最小化血缘 | 保护属性、代理和权利行为必须隔离；权利动作不能被普通暂停阻断 | 不代替业务批准或发布授权，不直接改画像 |
| Hiring Owner | 审阅 `当前版 → 候选版` 的证据、反证、未知、未来范围和风险摘要并提交决定 | 能选择批准、要求修改或拒绝；理解批准不等于授权或生效 | 看不到保护属性，不改研究口径、不替另一角色会签、不发布 |
| Profile Governance | 基于治理规则完成独立第二决定，并检查上一安全版本 | 双人批准后仍必须生成独立发布授权任务 | 不同一提案兼任用人负责人，不直接发布或回滚 |
| Publication Authorizer | 对精确当前提案、资格、未来范围、计划时间和回滚目标另行授权或拒绝 | 理解授权不等于发布准备、发布记录、同步或生效 | 不预授权旧提案，不替控制面准备或提交发布 |
| 招聘运营 | 查看逐系统版本、回执、等待对象、下次检查和最晚升级，并处理接管 | 部分同步不得显示全局成功；暂停使用优先，只能回到仍允许的版本 | 不改结果、研究或提案，不补签批准或绕过当前版本 |

## 7. 八个危险分支

每个分支至少由两名相关角色独立执行；不能只由研究员播放。若同一参与者覆盖多个分支，仍需保留每个分支独立的起始状态、操作和结果记录。

| ID | 危险分支 | 主要测试角色 | 预期安全终态 | 最小证据 |
|---|---|---|---|---:|
| HR-01 | 结果未成熟、来源冲突或后来更正 | Data Steward、Analyst | 保持未知/等待或进入对账；更正使旧派生物和旧任务失效 | 2 次独立执行 |
| HR-02 | 历史决定或仅录用者样本被当作真值 | Analyst、Privacy/Fairness | 展示完整分母与选择机制；阻断幸存者外推和历史偏见反馈环 | 2 次独立执行 |
| HR-03 | 评测口径、分区或重要人群伤害不可信 | Analyst、Privacy/Fairness | 只显示证据不足，不生成可发布提案 | 2 次独立执行 |
| HR-04 | 保护属性、代理变量或权利行为进入业务链 | Privacy/Fairness、Hiring Owner | 隔离并阻断；录制选择、辅助需求、申诉、删除等不影响画像或招聘结果 | 2 次独立执行 |
| HR-05 | 跨岗位、跨租户或不可比分组合并 | Analyst、Privacy/Fairness、招聘运营 | 无证据跨岗合并被拒绝；跨租户混用暂停相关业务效果并定界 | 2 次独立执行 |
| HR-06 | 删除、限制或用途失权后的全链召回 | Privacy/Fairness、Data Steward、招聘运营 | 停止读取/使用，派生物与导出按血缘失效；checkpoint 不恢复正文 | 2 次独立执行 |
| HR-07 | Agent 越权、同人兼签、缺失/旧授权任务或重复提交 | Hiring Owner、Profile Governance、Publication Authorizer | 无新版本或业务效果；旧任务只读；双人批准后仍需当前 HUMAN 独立授权 | 2 次独立执行 |
| HR-08 | 发布/同步部分失败与暂停使用/人工回滚竞态 | 招聘运营、Publication Authorizer | 逐系统显示实际版本；暂停优先、权利补偿继续、在途不迁移，只回到仍允许版本 | 2 次独立执行 |

## 8. 恢复性与可访问性验证

### 8.1 恢复性演练

至少执行以下演练：

1. 决定提交前刷新页面：恢复到当前权威任务，不保留未经提交的默认选择；
2. 打开旧版本或任务超时：旧任务只读，并能定位当前版本；
3. 快速重复点击或重试提交：界面只出现一个决定和一个当前事实；
4. 发布记录创建后部分同步：逐系统展示实际版本，不出现绿色总成功；
5. 权限被撤销后通过旧链接或深链访问：原型应展示拒绝与安全返回路径；服务端强制拒绝仍记为 `NOT_TESTABLE`；
6. Agent 暂停后人工接管：显示暂停范围、当前 Owner、恢复条件和恢复点；
7. 暂停使用与迟到发布竞态：暂停状态优先，迟到动作不能复活业务效果；
8. 删除、限制或用途失权：相关使用继续停止，checkpoint 或回滚不能恢复正文。

原型中的重复点击、深链拒绝和状态恢复只能形成交互证据。真实命令幂等、服务端授权和状态一致性必须在工程环境中另行验证。

### 8.2 可访问性走查

关键任务至少覆盖：

- 全程键盘导航、可见焦点、合理顺序、无键盘陷阱；
- 读屏下的标题、区域、控件名称、状态、错误提示和动态变化；
- 200% 缩放后的重排，无关键内容、操作或错误信息被裁切；
- 状态不只依赖颜色，文本、图标和结构语义一致；
- 正文和控件对比度达到适用的 WCAG 2.2 AA 目标；
- 长姓名、长岗位、长证据、长错误信息和中英文切换；
- 不同时区、日期跨日与计划生效时间表达；
- `prefers-reduced-motion` 下无必要动画被关闭，状态变化仍可理解；
- 弹窗、抽屉和返回后的焦点恢复正确。

若原型技术形态无法支持真实键盘或读屏操作，该项必须记为 `NOT_TESTABLE`，真人门不能宣称已达到 WCAG 2.2 AA。

## 9. 成功阈值与严重度

### 9.1 P0 硬门

以下全部为真才可通过真人门：

| Gate | 阈值 |
|---|---|
| 30 秒首屏理解 | 14/14 能说清系统正在做什么、当前责任人和截止时间 |
| 角色主要任务 | 每角色 2/2 `UNASSISTED_PASS` |
| 关键状态理解 | 关键误解为 0 |
| 八危险分支 | 8/8 分支均至少 2 次独立进入预期安全终态，共至少 16 次通过 |
| 禁止动作 | 无参与者能通过正常入口完成角色禁止动作；原型深链只计交互证据 |
| Activity Rail | 14/14 能找到等待对象、下次检查和最晚升级 |
| 暂停与接管 | 所有适用角色在两步内找到暂停/接管，且能准确说明作用范围 |
| 恢复演练 | 刷新、超时、旧版本、重复提交、部分同步、权限变化、暂停竞态均无第二个当前事实 |
| 无障碍 | 关键流程无键盘、读屏、焦点、200% 缩放、非颜色表达或 reduced motion 阻断 |

关键误解包括但不限于：

- 把 Agent 准备完成理解为画像提案、批准或生效；
- 把双人批准理解为已获发布授权；
- 把发布授权理解为控制面已准备或已发布；
- 把发布记录创建理解为所有下游已同步；
- 把部分同步理解为当前画像已全局生效；
- 把“正在停止”理解为“已经停止”；
- 把缺失、未知或删失理解为失败或负面能力；
- 把仅未来招聘生效理解为在途案件迁移；
- 认为 Agent、普通 Service 或任一单独审阅者可以代签或回滚。

### 9.2 P1 与 P2

- **P1**：影响主要任务完成、证据发现、后果理解、恢复或较大范围人工修复。修复前不得通过对应角色或分支，必须使用新版本和未见过旧流程的参与者复测。
- **P2**：不影响安全、任务完成或状态理解的局部效率、文案或视觉问题。可以进入有 Owner 和截止日的 Backlog，不得与 P0/P1 合并统计。

样本量为形成性研究下限，`2/2` 不代表统计泛化。它只用于阻止明显的角色、状态和安全问题进入下一阶段。

若研究期间发现 P0：

1. 立即停止受影响角色或分支的后续场次；
2. 冻结旧原型版本及已有证据；
3. 建立新版本与变更记录；
4. 使用未见过旧流程的候补参与者重跑所有受影响任务；
5. 不得将旧版本通过结果与新版本通过结果直接合并。

## 12. No-go 条件

以下任一项出现即真人原型门 No-go：

- 任一关键状态被误解为画像已经生效；
- Agent、Service、控制面或无权角色能够代替 HUMAN 作批准、授权、发布决定、恢复使用或回滚；
- 缺失被当作失败，部分同步被显示为全局成功，或旧任务仍可提交当前决定；
- 删除、限制、用途失权、暂停、权限撤销或更正不能优先阻断并给出恢复；
- 任一危险分支没有明确安全终态、Owner、下次检查、最晚升级或恢复点；
- 任一角色未获得两名真实职责参与者，或以项目成员/相邻岗位代理；
- 任一 P0 或影响主要任务的 P1 尚未完成独立复测；
- 关键流程存在键盘陷阱、无名控件、焦点丢失、颜色单独传意、200% 缩放后操作缺失或读屏无法理解；
- 原型、fixture、操作记录或修复版本无法追溯；
- 将原型中的按钮隐藏、模拟拒绝或模拟去重宣称为服务端权限或幂等已经验证；
- 用视觉偏好、设计 Token 一致、Demo 顺利或研究员代操作替代真人任务证据。

即使不存在上述问题，若服务端权限、幂等、数据合法性、真实连接器或生产恢复仍无证据，项目总 Gate 继续保持 No-go；本计划不能越权改变该结论。
