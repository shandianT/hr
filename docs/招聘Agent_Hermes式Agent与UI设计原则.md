# 招聘 Agent：Hermes 式 Agent Harness 与 UI 设计原则

版本：v0.1
日期：2026-08-10
状态：跨 G1–G3 的产品与交互设计基线

## 1. 设计结论

招聘 Agent 不应被设计成一个“会聊天的 ATS”，也不应把后台任务包装成炫目的 AI 大屏。它应像一位可靠、安静、一直在线的招聘专员：正常路径自动推进，只在需要人作判断时出现；任何动作都可解释、可暂停、可恢复、可追溯。

本项目借鉴 Hermes Agent 公开架构中的可观察执行、可中断 Agent Loop、平台无关核心、松耦合工具注册、隔离运行、持久会话、技能复用和 checkpoint/rollback 思路，但不把采用 Hermes Agent 代码库当作已决定的技术选型。

“Hermes 式”只是 **Agent harness 的工程隐喻**，不是产品名、视觉品牌或 UI 风格。业务界面不出现 Hermes 标志、神话意象或“按 Hermes 做皮肤”的要求；设计语言仍由招聘任务、信任、可访问性和真人可用性决定。

这里的“Hermes 式”指一组 harness 工程原则：

1. Agent 有持续运行的编排循环，但模型不是业务状态机。
2. 工具调用、审批、进度、回执和失败对用户可见。
3. 运行可以被暂停、打断、恢复和安全回滚。
4. 入口可以是控制塔、IM、候选人页或后台任务，但共用一个权威核心。
5. 记忆和技能可以积累，但只能生成版本化建议，不能自行改变招聘规则。
6. 不同租户、岗位、案件、角色和子 Agent 的上下文严格隔离。

## 2. Agent Harness 基线

~~~mermaid

    ORCH --> WORKERS["专用 Agent Workers\n理解 · 提取 · 生成 · 比较"]

    ACTION --> EXT["外部系统"]
    EXT --> RECEIPT["Provider Receipt / Reconciliation"]
    RECEIPT --> DOMAIN["领域聚合提交业务事实"]
    DOMAIN --> ORCH
    POLICY["版本化策略 · Skills · Memory"] -.只读输入.-> ORCH
    AUDIT["审计 · 指标 · 回放"] --- ORCH
~~~

### 2.1 一个运行循环

每次工作遵循同一循环：

1. **Observe**：读取当前权威事实和外部回执，不依赖过期页面状态。
2. **Plan**：生成有限步骤、预算、风险和预期结果。
3. **Propose**：模型输出材料或动作建议，不写业务状态。
4. **Authorize**：确定性策略门或有权限的人批准具体命令。
5. **Execute**：通过 ActionExecution 执行工具或连接器动作。
6. **Reconcile**：核对外部世界与内部事实，不把“已请求”冒充“已成功”。
7. **Commit**：拥有该事实的聚合提交状态和 Outbox 事件。
8. **Learn safely**：运行轨迹只进入质量复盘或版本建议，不自动改变策略、画像或权限。

### 2.2 专用 Agent，而不是一个全能 Prompt

建议按职责拆成可替换 Worker：

| Worker | 负责 | 永远不能做 |
|---|---|---|
| Intake Agent | 附件识别、解析、路由候选、重复信号 | 自动合并身份、无路由开案 |
| Screening Agent | 逐维证据、未知项、反证、追问建议 | 排名、淘汰、隐藏低分申请 |
| Coordination Agent | 时段提案、改期计划、提醒计划 | 伪造 Booking、替候选人选时 |
| Interview Evidence Agent | 纪要、证据定位、评价草稿 | 伪造证据、替面试官确认 |
| Case Steward Agent | SLA、下一动作、异常打包、恢复建议 | 绕过命令门直接改状态 |
| Profile Governance Agent | 结果归一化、队列体检、画像变更草案 | 把历史结果当真值、自动发布画像 |

Worker 可以并行，但跨 Worker 只交换最小结构化引用和事件；每个 Worker 有独立预算、超时、可用工具、数据作用域和失败降级。

### 2.3 Memory 与 Skill 的边界

- **业务事实不放在 Agent 记忆里**：案件、决定、画像版本、同意、权限和回执必须来自权威系统。
- **Memory 只保存工作偏好和可复用上下文**：例如某部门习惯的面试时长；使用前仍要经过当前策略和权限校验。
- **Skill 是版本化流程资产**：每个 Skill 有输入/输出 Schema、允许工具、权限、预算、失败码、测试集和 Owner。
- **自我改进只产生 Candidate Skill Revision**：必须经过离线回放、危险场景、产品/技术/QA 审核后才可启用。
- **候选人材料和模型输出都不是可执行指令**：Prompt injection 不得改变 Skill、Memory、工具或权限。

### 2.4 Checkpoint、恢复与回滚

在以下动作前建立可定位的业务 checkpoint：

- 发布新画像/评分卡/流程/Prompt/Skill 版本；
- 批量外发、批量迁移或重新计算；
- 提升某类动作的 A0–A3 放权等级；
- 执行可回滚的配置变更、补偿或连接器资源替换；
- 引入新模型、供应商、租户配置或跨系统映射。

Checkpoint 必须包含版本清单、策略、适用范围、待执行动作、外部资源引用和回滚方案。回滚不是覆盖历史：新案件回到上一批准版本，在途案件保持原钉住版本或进入显式影响评审。

删除、限制使用、撤回同意、纠正和停止处理属于权利或安全动作，**不授予 checkpoint 保留或恢复正文的权力**。执行这类动作时只保留最小化的范围、策略版本、时间、不可逆完成回执和无正文墓碑；任何恢复、回放或回滚在读取前都必须重验当前用途、权利和删除状态，命中已删除或已限制数据时拒绝恢复。Checkpoint 只能证明动作范围和完成情况，不能复制、重建或重新引入应删除的数据。

### 2.5 可观察但不过度暴露

每个 Agent Run 对授权用户提供五项信息：

1. 当前在做什么；
2. 为什么触发；
3. 使用了哪些版本化输入；
4. 外部动作与回执是否完成；
5. 失败后会自动恢复还是需要人处理，以及当前等待对象、下次检查时间和最晚升级时间。

默认不展示模型长推理、Prompt、密钥、完整简历/逐字稿或内部安全策略。用户看到的是可审计事实、简洁理由和下一步。

## 3. UI 产品哲学

### 3.1 Quiet by default

正常案件不占据用户注意力。首页优先展示：

- **需要你决定**：只能由当前用户完成的人审点；
- **Agent 正在处理**：可折叠的在途动作、当前等待对象、下次检查时间与最晚升级时间；
- **有风险**：接近 SLA、外部状态不一致或安全闸门阻断；
- **已完成**：作为轻量回执，不制造通知噪音。

不展示没有证据基础的“预计还要几分钟”。外部系统或人类响应不可预测时，宁可诚实显示在等谁、何时再查和何时升级。

不把“总候选人数”“模型调用次数”“自动化百分比”等装饰性数字放在首屏中心。

### 3.2 One primary action

每张人审卡片只突出一个当前主要动作，并清楚回答：

- 你为什么现在看到它；
- Agent 已经完成了什么；
- 依据是什么、还有什么未知；
- 你的选择会产生什么效果；
- 如果不处理，何时升级。

次要动作进入二级菜单；危险动作需要明确后果和可恢复范围，不能用模糊的“确认”按钮。

### 3.3 Progressive disclosure

同一信息分三层：

1. **结论层**：状态、下一动作、责任人、截止时间。
2. **依据层**：证据、未知、差异、风险和 Agent 已尝试动作。
3. **审计层**：版本、事件、命令、回执、权限和完整时间线。

默认停在第一层；专业用户可以逐层展开，不用在信息极少与全量日志之间二选一。

### 3.4 Chat is a command surface, not the product shell

聊天/自然语言可以用于搜索、解释、批量意图和草拟操作，但不能成为唯一入口。所有高频任务都有稳定可发现的图形界面；自然语言产生的动作必须回到相同的预览、权限、版本和回执流程。

### 3.5 普通用户信息架构与语言

业务端主导航控制在六项以内：

1. **首页**：需要决定、Agent 正在处理、风险与最近完成。
2. **招聘任务**：按岗位、负责人、阶段和时限查看案件。
3. **面试**：排期、面前简报、面后确认与多轮协同。
4. **终面评估**：待补全、已就绪和已失效的终面评估材料。
5. **异常与接管**：需要人处理的最小异常包及恢复入口。
6. **设置与治理**：只对授权管理角色可见；动作权限、连接器、审计和**画像治理**均为此处的子导航，不把画像治理做成所有人的一级入口。

候选人移动端协调页是独立安全链接，不占业务端主导航。角色无权进入的治理页面应隐藏入口，并在旧链接或深链访问时由服务端再次拒绝，不能只把按钮置灰。

普通业务界面只使用可理解的中文；内部枚举和风险码只进入授权审计抽屉。例如：

| 内部语义 | 普通界面用语 |
|---|---|
| STOPPING | 正在停止处理，请稍候 |
| P0 | 严重风险，相关操作已暂停 |
| Cohort | 分析样本与覆盖范围 |
| Freeze | 已暂停使用此版本 |
| A0 | 仅做后台验证，不影响实际招聘 |

翻译不能丢掉状态差异：“正在停止”不冒充“已经停止”，“暂停使用”不冒充“已经回滚”。

## 4. 核心交互组件

| 组件 | 解决的问题 | 必须展示 |
|---|---|---|
| Agent Activity Rail | 让长任务有进度但不占满页面 | 当前阶段、已完成步骤、等待对象、下次检查、最晚升级、暂停入口 |
| Decision Card | 让人类只处理不可替代的判断 | 依据/未知、选项后果、当前版本、截止时间、唯一主要动作 |
| Evidence Drawer | 在不淹没页面的情况下证明结论 | 原文/时间戳、来源角色、置信与局限、版本 |
| Case Timeline | 串联简历、消息、日历、面试、评价与决定 | 业务事件与 Agent 动作分层、补偿/失效可见 |
| Exception Bundle | 把报错变成可决策任务 | 事实、尝试、影响、选项、建议、Owner、恢复点 |
| Version Diff | 审查画像、评分卡、Prompt、Skill 变化 | 新旧差异、依据、影响范围、评测、批准与回滚 |
| Reconciliation Panel | 处理内部/外部不一致 | 两侧事实、最后核对时间、自动修复计划、人工选项 |
| Trust Receipt | 给候选人/员工证明告知、选择和权利动作 | 目的、范围、当前选择、撤回/删除入口和完成回执 |

## 5. 角色化体验

### HR / 招聘运营

- 首屏不是全量候选人表，而是“今天需要决定什么”。
- 批量处理只用于同规则、同风险、同版本的任务；不把招聘决定做成一键批量自动化。
- 例外中心按可决策问题聚类，不按技术错误码堆积。

### 用人负责人

- 只看到本岗位、当前请求和最小必要候选人信息。
- 匹配材料同时展示支持、反证和未知，不只给正向摘要。
- 决定提交后明确显示“已由谁在何时基于哪个版本提交”。

### 面试官

- 面前只展示本轮问题和证据缺口，避免前轮结论锚定。
- 面后先核对证据与纪要，再确认评价；修改路径比从零写更省事。
- 低置信、多人发言和无录制笔记局限在原位置可见。

### 候选人

- 移动优先，不要求注册复杂账号；身份核验与链接用途明确。
- 时间、时区、改期、录制选择和权利入口在同一协调体验内完成。
- 不展示内部匹配分、评语或“AI 正在评估你”等制造压力的信息。
- 拒绝录制与同意录制拥有等价的面试机会和完成反馈。

### 画像治理人

- 先看到“为什么建议改、证据够不够、有哪些偏差风险”，再看参数差异。
- 发布前必须完成版本 Diff、离线/影子评测、公平与隐私门、影响范围和回滚预览。
- 历史结果更正或删除后，相关分析样本、评测和提案显式失效。

### 5.1 G3 角色、可见信息与动作分离

画像治理页必须按角色裁剪可见信息和主要动作。所有审阅选择默认均不选中；需要作批准、要求修改或拒绝判断的角色，页面唯一主按钮统一使用中性的 **“提交你的决定”**，不能用“批准并生效”诱导，也不能让按钮文字冒充后台发布结果。

| 角色 | 可以看到 | 唯一主要动作 | 明确禁止 |
|---|---|---|---|
| 用人负责人（Hiring Owner） | 当前版与候选版差异、业务依据、反证/未知、未来适用范围、风险摘要 | 提交你的决定 | 改研究口径、看保护属性、单独发布、替另一角色会签 |
| HRBP / 画像治理负责人（Profile Governance） | 上述内容、治理规则、另一角色决定、未来范围与上一安全版本 | 提交你的决定 | 兼任同一提案的用人负责人、改结果标签、把共同批准冒充发布授权、直接执行发布或回滚 |
| 发布授权人（Publication Authorizer） | 双人批准完成事实、精确提案/资格/未来范围、计划生效时间、关键同步集、上一安全版本与回滚目标 | 提交你的决定 | 预授权或授权旧提案、从批准推导授权、替控制面执行发布准备/提交指针、由 Agent 或 Service 代签 |
| 结果数据管理员（Data Steward） | 来源冲突、结果阶段、成熟/缺失/删失、纠正血缘与处理队列 | 提交对账结果 | 评价候选人优劣、批准提案、授权或发布画像、改招聘决定 |
| 隐私 / 公平负责人（Privacy/Fairness） | 用途、样本覆盖、重要人群伤害、代理风险、删除/限制状态和最小化血缘 | 提交风险审查 | 把保护属性带入业务画像、代替业务批准或发布授权、直接改候选人或岗位结论 |
| AI / 数据分析师（Analyst） | 固定分析样本与分区、候选生成清单、预先登记的口径、独立测试样本开启记录、指标/区间与因果边界 | 提交研究审查 | 看过独立测试结果后反向调候选、改变既定分区或口径、批准/授权/发布/回滚画像 |
| 招聘运营 | 当前生效版本、下游回执、同步异常、等待对象、下次检查和最晚升级 | 提交接管方案 | 改观察/标签/研究/提案、补签批准、绕过当前版本 |
| Agent / 自动化服务 | 完成任务所需的最小版本化输入、工具权限和回执 | 无业务决定按钮 | 确认真值、选择提案、批准、授权、发布、解冻或回滚 |

双人批准完成后，必须新建一项独立的发布授权人任务；具备当前发布权限的 HUMAN 对精确提案、资格、未来范围、计划生效时间与回滚目标另行提交决定，才形成发布授权。授权人可以与一名批准人是同一自然人，但必须以独立发布权限、独立任务和独立签名完成，不能从批准记录推导。发布随后才由确定性控制面执行，不属于 Agent、普通 Service 或任一审阅者的隐含权限。拒绝、要求修改、撤回批准和拒绝授权必须与正向决定同样可达、可键盘操作、可审计。

### 5.2 Agent、提案、发布三类状态

三个对象分别投影，任何一个对象的完成都不能替另一个对象显示成功：

| 对象 | 普通界面状态示例 | 绝不能推导 |
|---|---|---|
| Agent 工作 | 正在收集、等待数据、等待人处理、已受阻、准备工作已完成 | “准备完成”不等于形成提案、获批或生效 |
| 画像提案 | 草稿、待两方分别决定、要求修改、已拒绝、双人已批准、待发布授权、已失效 | “双人已批准”不等于已经授权、创建版本、发布或同步 |
| 发布授权、发布与同步 | 发布授权任务待处理、已拒绝授权、已获当前授权等待准备、发布准备中、发布记录已创建等待同步、同步未完成、已生效、已暂停使用、已回滚 | “批准”不等于“授权”；“授权”不等于控制面已准备、已提交或所有下游已生效 |

发布体验按两阶段呈现：

1. **授权与发布准备阶段**：两名不同职责的人分别批准后，只显示“双人已批准，待发布授权”并生成独立发布授权人任务；当前 HUMAN 另行授权精确范围后，才显示“已获当前授权，等待发布准备”。确定性控制面随后重验授权、当前基础版本、用途、未来范围和上一安全版本；创建不可变发布记录后只显示“发布记录已创建，等待同步”，不显示“已生效”。
2. **同步与生效阶段**：逐一核对当前版本指针和所有必需下游回执；全部一致才显示“已生效（仅未来招聘）”。部分失败显示“同步未完成”，明确每个系统实际使用的版本、当前等待对象、下次检查和最晚升级，不能用绿色总状态掩盖差异。

状态词典必须固定表达：**批准不等于授权，授权不等于发布准备，发布准备不等于生效**。任何页面、通知、活动轨或总览都不得省略中间事实。

任一相关结果被更正/删除、用途失权或严重风险出现时，旧提案和旧决定立即失效；暂停使用优先于迟到的发布。权利动作继续执行且不受暂停阻断，人工回滚只指向此前批准且当前仍允许的版本。

### 5.3 G3 原型正常链与八个危险分支

G3 正常链固定为：批准来源进入 → 结果观察与修订对账 → 成熟/资格判断 → 固定完整分析样本与分区 → 先冻结研究计划和候选修订、再打开独立测试样本 → 当前版与候选版离线比较 → 形成可审提案 → 两名不同职责的人分别提交批准决定 → 独立发布授权人提交当前 HUMAN 授权 → 确定性控制面发布准备（仅未来招聘）→ 必需下游同步与对账 → 确定性控制面提交当前版本指针并确认生效 → 按真实未来使用情况监控。任一门不通过时只等待、拒绝或形成异常包，不自动调权。

原型必须使用同一组八个危险分支：

1. **结果尚未成熟、来源冲突或后来更正**：保持未知/等待或交给结果数据管理员，不把缺失当失败；更正使所有旧派生物和旧任务失效。
2. **历史决定或仅录用者样本被当作真值**：显示完整分母和选择机制，阻断“旧画像选择谁 → 只有被选择者产生结果 → 再证明旧画像正确”的反馈环，不把旧拒绝/录用或幸存者结果外推为候选人能力及全漏斗因果结论。
3. **评测口径、分区或重要人群伤害不可信**：候选修订未先锁定、偷看测试样本、小样本/宽区间、同人穿透分区或重要人群退化时，只显示证据不足，不生成可发布提案。
4. **保护属性、代理变量或权利行为进入业务链**：隔离并阻断；姓名、学校、口音、邮编以及录制选择、辅助需求、申诉、删除请求等不得影响画像或招聘结果。
5. **跨岗位、跨租户或不可比分组合并**：无可比证据的跨岗合并被拒绝；跨租户混用立即暂停相关业务效果、定界和处置。
6. **删除、限制或用途失权后的全链召回**：停止读取和使用，结果标签、分析样本、评测、提案、导出与看板按血缘失效并给出回执；checkpoint 不得恢复正文。
7. **Agent 越权、同人兼签、缺失/旧授权任务或重复提交**：没有新版本或业务效果；旧批准/授权任务只读，两个不同职责的人必须分别提交当前批准决定，之后仍需当前发布授权人完成独立任务；批准不能推导授权，Agent、Service 或控制面不能代签。
8. **发布/同步部分失败与暂停使用/人工回滚竞态**：逐系统显示实际状态；暂停使用优先，权利补偿继续，在途案件不迁移，人工只能回到此前批准且仍允许的版本。

## 6. 视觉系统方向

### 6.1 气质

关键词：**专业、安静、可信、精确、克制**。

- 不是赛博朋克，不使用霓虹线条、持续发光、机器人头像或大面积动态渐变。
- 不用玻璃拟态掩盖层级；必要的浮层仍保持清晰边界和对比度。
- AI 状态用文字、图标和轻量动效表达，不用无休止“思考中”动画制造智能感。

### 6.2 参考 Token（不是品牌规范）

以下色值只是帮助首版原型建立语义层级的参考，不是冻结的品牌资产或验收像素值。设计师可以提出更好的等价系统，但必须保持语义稳定、文本对比度、非颜色冗余和跨状态可辨认；不能用“与参考色号完全一致”代替可用性证据。

| 用途 | 方向 |
|---|---|
| Canvas | 温暖浅灰 `#F6F7F5`，降低医疗/金融后台的冰冷感 |
| Surface | 白色 `#FFFFFF` 与二级灰 `#EEF1ED` |
| Primary text | 石墨黑 `#161A18` |
| Secondary text | 中性灰 `#5E6762` |
| Agent accent | 克制钴蓝 `#315EF4`，只用于进行中和主操作 |
| Verified | 深青绿 `#167465`，表示已核对而非笼统“好” |
| Risk | 琥珀 `#B66A12`，表示需关注 |
| Destructive | 深红 `#B4233C`，仅用于危险与阻断 |

状态不能只依赖颜色；每个状态同时具备文字、图标或形状。中英文使用清晰的人文无衬线字体，数字/版本/时间采用 tabular numerals。

### 6.3 布局与动效

- 12 列网格和 8px spacing 可作首版参考，最终以内容层级、200% 缩放重排和舒适阅读宽度为准，不作为机械验收值。
- 卡片圆角和阴影克制，边界主要依赖间距、底色和排版层级。
- 动效只解释状态变化，160–220ms 仅作参考；支持 `prefers-reduced-motion`，关闭动效后信息不丢失。
- 表格在窄屏转为摘要卡，不做横向无限滚动的候选人“Excel 墙”。
- 重要 CTA、暂停与撤回入口在键盘和触控场景都可访问。

## 7. 可用性与信任验收

任何新原型至少满足：

1. 正常案件无需 HR 点击“开始”，但当前进度和下一动作可在一个页面确认。
2. 人审卡片只有一个视觉主要 CTA，且提交前能看到业务后果。
3. 授权用户在两步内可以暂停相关 Agent 流程，并看到暂停范围。
4. 每个外部动作都能定位到触发原因、输入版本、ActionExecution 和回执/对账结果。
5. 所有异常都能回答“谁处理、何时到期、Agent 已做什么、处理后从哪里恢复”。
6. 不以颜色单独表达关键状态；键盘导航、焦点、对比度和缩放达到 WCAG 2.2 AA 目标。
7. 候选人移动端完成选时/改期/采集选择的流程无需阅读内部术语。
8. 页面不会把 Proposal 显示成 Booking、告知显示成同意、AI 草稿显示成人工决定、规格 CI 显示成工程完成。
9. 用户中断或刷新页面后，能从权威事实恢复，不依赖前端本地状态。
10. 设计走查同时覆盖正常链、旧版本、重复回调、部分成功、权限变化、撤回/删除和安全熔断。
11. G3 由用人负责人（Hiring Owner）、HRBP / 画像治理负责人（Profile Governance）、发布授权人（Publication Authorizer）、结果数据管理员（Data Steward）、隐私 / 公平负责人（Privacy/Fairness）、AI / 数据分析师（Analyst）和招聘运营七类 HUMAN 逐角色走查“可见信息、唯一主要动作、禁止动作”；无权角色从导航和深链都不能完成被禁止动作。
12. G3 正常链与八个危险分支均能恢复到一个明确状态，且不把 Agent 完成、提案双人批准、发布授权、发布准备、发布记录创建、下游同步或当前生效互相冒充。
13. Activity Rail 对不可预测工作展示等待对象、下次检查和最晚升级，不编造精确完成时间；刷新、超时、部分成功和接管后仍可继续。
14. 视觉评审通过不能单独放行。发布证据必须同时包含关键任务成功率与关键误解、恢复演练、键盘/读屏/200% 缩放/reduced motion 结果，以及不同角色对状态和后果的理解记录。

## 8. 采用边界

- 当前只冻结产品和 harness 原则，不代表已经选择 Hermes Agent 作为生产运行时；“Hermes 式”也不是 UI 品牌。
- Hermes 的通用自学习机制不能原样用于招聘：任何 Memory、Skill、Prompt、画像或策略变化都必须经过租户隔离、合法用途、评测、人工批准和回滚门。
- 高级视觉不能替代连接器可靠性、数据合法性、证据质量或用户采用证据。
- 旧的控制塔 HTML 只保留为危险分支逻辑参考，不作为视觉或交互基线。
