# 招聘 Agent 产品形态 Demo

状态：`PROTOTYPE / SYNTHETIC_ONLY`

直接双击 `招聘Agent_产品形态Demo_v1.html` 即可运行，无需安装依赖、启动服务或连接网络。

如果要先看第一个已经拆成真实产品切片的核心功能，直接打开 `招聘Agent_核心功能1_简历收件Demo.html`。它展示：

- 批准来源与附件安全门；
- 带原文定位的结构化简历版本；
- 邮箱 + ATS 重复来源但不重复建案；
- 身份冲突和岗位 / 周期冲突的必要人工判断；
- 简历提示注入隔离；
- 唯一路由后的自动开案回执。

页面内置六个完全虚构的样例，不提供真实文件上传入口。正常样例点击「自动演示」会走到 `ApplicationCaseOpened`；冲突样例会停在安全边界，人工提交判断后 Agent 自动恢复。总 Demo 的三个方案都提供「体验简历收件」入口。

第二个已拆成可验收产品切片的核心功能是 `招聘Agent_核心功能2_画像匹配与部门决定Demo.html`。它展示：

- 默认只走“简历与岗位 → 筛选卡 → 用人负责人决定”三步，第一次打开只显示一个主按钮；
- 筛选卡先给一句中性摘要，再将材料分为关键支持、待核实和风险或证据不足；原文证据按需展开；
- 不显示总分、排名或 Agent 推荐，也不预选“进入一面 / 稍后复核 / 本岗位不推进”；
- 版本、Agent Activity、SLA、静默时段与回执统一放进“运行详情”；
- 八个安全场景收进“测试其他情况”，保留低证据人审、禁用信号阻断、材料更新、暂缓恢复、超时、错误收件人与越权/旧卡/双击边界。

页面内置八个完全虚构场景：`normal`、`lowEvidence`、`prohibited`、`versionChanged`、`hold`、`overdue`、`recipientError` 和 `authority`。可从仓库根目录运行 `node prototype/check_screening_demo.mjs` 复验独立状态机。Demo 与 Python 内核尚未打通，不接真实模型、IM/邮件、IAM 或任何外部效果。

第三个核心功能切片是 `招聘Agent_核心功能3_候选人约面Demo.html`。它从候选人视角展示：

- 候选人只需选择一个当前可用时间；选择完成后明确显示“现在还不是已预定”；
- Agent 在后台分别确认日历占位、会议链接和邀请写入，三个当前修订回执齐全后才显示“面试已安排”；
- 录制告知和候选人的录制选择独立于预约，默认不替候选人选择；选择“不录制”不影响面试安排；
- 改期确认期间保留旧安排，旧修订回调、重复回调、忙闲变化、暂停/关闭、错误收件人和响应丢失等十二个场景收进“测试其他情况”。

可从仓库根目录运行 `node prototype/check_scheduling_demo.mjs` 复验独立状态机。Demo 不连接真实日历、会议、邀请、身份系统或录制能力；所有回执与外部效果均为合成。

默认方案是 B「候选人旅程」。底部左右箭头可切换：

- A：控制室，侧重完整状态、SLA 和最终交付件；
- B：候选人旅程，侧重十秒内讲清端到端产品承诺；
- C：运营工作台，侧重多案件队列和 Agent Activity。

验证操作：

1. 点击「自动演示」，观察 Agent 在必要人工决策点自动停下；
2. 提交部门筛选决定和面试官评估确认，或尝试「暂缓并说明 / 要求修改」，检查分支、原因与恢复点是否被保留；
3. 观察一面、二面、终面的多轮循环；为了快速讲清产品，Demo 会快速回放前两轮，完整展示终面；
4. 切换「录制同意缺失」、「日历时段冲突」或「部门反馈超时」，查看安全路线、检查点、重试次数和恢复记录；
5. 主线完成后打开「终面评估包」，查看三轮结论、证据引用、风险、未解问题和人工确认记录；
6. 在任一进度切换 A / B / C，三种产品形态会保留同一案件状态。

页面应始终能回答：Agent 在做什么、在等谁、下一步是什么、何时会再次行动，以及为什么能恢复。

该文件是为了快速确认产品形态的一次性原型。所有候选人、岗位、动作和回执均为合成数据；它不证明真实邮箱、日历、会议、消息外发或服务端权限已可用。
