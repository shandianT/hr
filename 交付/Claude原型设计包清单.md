# Claude 原型设计包清单

生成日期：2026-08-10  
包版本：v3（31 个文件，扁平目录）
用途：供 Claude 从零设计招聘 Agent 高保真可点击原型

## 设计统一口径

- “Hermes 式”只表示 Agent harness 工程隐喻，不是产品名、UI 品牌或既定 runtime；精确色值、间距和动效数值仅作参考。
- 普通业务端只有 5–6 个一级导航；画像治理位于“设置与治理”的授权子导航。
- G3 原型必须同时覆盖一条治理正常链和八个统一危险分支，并分开表达 Agent 工作、画像提案、发布/同步三类状态。
- 画像审阅唯一主按钮使用中性“提交你的决定”；批准、发布、同步和当前生效互不冒充。
- 普通页面使用中文业务语言，内部运行码、风险码、样本术语、暂停码和动作权限码只进入授权审计抽屉。

## Must Read

开始设计前必须阅读，以下文件直接决定产品目标、信息架构、角色、CTA 和状态语义：

- `Claude原型设计任务书.md`：设计目标、六项 IA、页面、两条正常链、八个 G3 危险分支与验收标准。
- `招聘Agent_Hermes式Agent与UI设计原则.md`：可观察、可中断、可恢复的 harness 与 UI/无障碍证据门；不代表 runtime 或 UI 品牌选型。
- `招聘Agent产品落地总方案.md`：完整产品策略、阶段、团队、指标和风险。
- `CONTEXT.md`：统一业务语言。
- `招聘Agent_G1_MVP_PRD.md`：单轮面后证据闭环。
- `招聘Agent_G1b_终面评估包_PRD.md`：多轮串联、面前简报和终面评估包。
- `招聘Agent_G2_收件筛选约面_PRD.md`：收件、路由、匹配、部门决定、约面、采集与 G1 交接。
- `招聘Agent_G3_结果回流与画像治理_PRD.md`：结果观察、完整分析样本、预先登记的评测、画像候选修订、双人决定与仅未来招聘发布。

## Product Reference

遇到对象边界、危险分支、版本失效或真实进度时查阅；不要把工程字段直接搬到普通 UI：

- `产品方案总册.md`：用户提供的原始背景；与后续规格冲突时以后续规格和红线为准。
- `招聘Agent_领域与事件规格.md`：案件、轮次、会话、动作、异常和版本规则。
- `0001`–`0009` ADR：关键架构/产品决策，尤其注意“时段提案不等于预定”“录制告知不等于采集授权”和“结果观察不是真值”。
- `招聘Agent_G2_需求追踪矩阵.md`：G2 正常/危险验收覆盖。
- `招聘Agent_G3_需求追踪矩阵.md`：G3 需求、危险场景与横向证据门。
- `招聘Agent推进看板.md`：当前已证实、未验证、等待对象与下一放行证据。
- `招聘Agent_Gate0执行包.md`：试点、数据、集成、质量与合规放行模板。

## 有意不包含

- 旧的 `招聘Agent控制塔_逻辑原型.html`：用户已否定其设计，为避免锚定不放入本包。
- 旧原型验收记录：只证明旧原型的内部逻辑检查，不应影响新设计方向。
- JSON Schema、lint 脚本和本地学习日志：对原型视觉/交互设计不是必要输入。
- 任何真实候选人、邮箱、日历、会议、录音或凭据数据。
