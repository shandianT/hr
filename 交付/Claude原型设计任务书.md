# 招聘 Agent 原型设计任务书（给 Claude）

## 1. 你的角色

你是一名资深企业软件产品设计师和交互设计师。请基于随包产品资料，从零重新设计一套高保真、可点击的招聘 Agent 原型。不要复用或模仿任何旧原型；本包刻意不提供旧 HTML，以避免视觉和交互锚定。

## 2. 产品目标

把“简历落进收件源”到“终面评估材料摆上最终决策人的桌面”作为一个完整中段交给 Agent，像交给一个不休息的招聘专员：

> 接收简历并解析 → 唯一路由到候选人/岗位/周期 → 按岗位画像形成有证据的匹配材料 → 推送用人部门并有限催反馈 → 读取授权日历并协调候选人 → 创建会议邀请 → 面前分发追问简报 → 面后生成纪要和证据化评价草稿 → 催面试官确认 → 串联各轮 → 形成不可变终面评估包 → 无法继续时交付异常包。

“无需 HR 触发”是指流程由来源事件自动启动、正常推进不依赖 HR 搬运；它不等于无人决策。部门邀请/拒绝、各轮推进和最终录用/淘汰始终由有权限的人作出。

## 3. 当前事实边界

- 当前材料是产品与控制规格，不是已经上线的系统。
- G1a（单轮面后闭环）和 G1b（多轮与终面评估包）已有评审规格。
- G2（收件、筛选、部门决定、约面、同意、采集闸门与 G1 交接）已有 v0.2 评审规格；它只代表产品边界成稿，仍没有工程、真人、连接器或合规批准证据。遇到未定义体验细节请形成设计假设并显式标注，不要替产品作高风险决定。
- G3（结果观察、固定分析样本、离线评测、画像候选修订、双人批准与未来周期发布）已有 v0.1 产品规格；当前只证明规格结构，不代表真实任职后数据、统计/公平有效性、任何动作权限级别或画像发布已放行。
- “Hermes 式”只是 Agent harness 的工程隐喻，不是产品名、UI 品牌或视觉风格，也不代表已选择 Hermes Agent runtime：模型只产建议，确定性控制面拥有权限/状态/工具动作；运行可观察、可暂停、可恢复、可对账。不要在业务界面使用 Hermes 标志、神话意象或品牌化文案。
- 当前发布结论为 No-go：不得把原型演示理解为真实邮箱、日历、会议或个人信息处理已经放行。

## 4. 核心用户

1. **用人部门负责人**：快速审阅匹配材料，作进入面试/拒绝/保留等人工决定，处理升级事项。
2. **面试官**：在面前获得不造成锚定的追问简报；面后核对证据和评价草稿并作人工轮次决定。
3. **最终招聘决策人**：审阅跨轮证据、信息不足、豁免和冲突，主动提交最终决定。
4. **招聘运营 / HR**：监督托管质量、SLA、异常和接管，不负责逐案手动发起正常步骤。
5. **候选人**：在移动端选择时段、改期、查看必要信息、选择录制或无录制路线、撤回选择。
6. **隐私 / 质量 / 系统运营人员**：处理越权、错误收件人、同意撤回、删除、偏见和可靠性事件。
7. **画像治理负责人 / 结果数据管理员**：前者参与画像审阅与双人决定，后者只处理结果冲突、成熟状态、纠正血缘和样本质量；两类职责不能合并成一个“超级管理员”。
8. **发布授权人**：在双人批准后处理一项独立 HUMAN 任务，对精确提案、未来范围、计划生效时间与回滚目标另行授权；不负责替控制面发布。
9. **AI / 数据分析师**：审查固定分析样本、分区、预登记口径、独立测试样本开启顺序、指标区间和因果边界；不参与业务批准或发布授权。

## 5. 体验设计原则

1. **业务任务优先**：业务用户首先看到“现在需要我做什么、依据是什么、截止何时、不处理会怎样”，而不是领域状态枚举和技术日志。
2. **案件主线清晰**：同一候选人的不同岗位/周期严格隔离；案件详情用一条可解释时间线串起材料、决定、会话和外部回执。
3. **证据优先于分数**：匹配与评价中的关键判断可一键回到简历或逐字稿证据；信息不足明确显示，不能补写成负面结论。
4. **人类决定低摩擦但不含糊**：所有招聘决定显示决定人、权限、依据版本和后果；不预选、不诱导、不由模型代提交。
5. **自主与可控并存**：正常链安静自动推进；暂停、撤回、删除、权限撤销和严重风险能立即压过待执行动作。内部风险码只进入授权审计抽屉。
6. **异常就是决策包**：异常页面提供事实、Agent 已尝试动作、风险、可选方案、建议、Owner 和截止时间，而不是只有错误码。
7. **候选人体验独立设计**：协调页移动优先、语言清楚、操作少；拒绝录制不影响面试机会，并有等价无录制路线。
8. **分阶段披露**：下一轮面试官在提交独立评价前，只看到本轮评分卡、证据缺口和建议问题，默认不看前轮总分、结论或决定。
9. **请求不冒充事实**：候选人选时不等于预定，采集开始/停止请求也不等于平台已开始/已停止；界面要诚实展示等待确认、状态不明和对账。
10. **控制有明确范围**：撤回、限制和删除必须显示作用于哪个案件/会话、目的和数据；候选人撤回一个岗位不默认关闭其他岗位，参与人的采集选择也不是全局开关。
11. **Quiet by default**：正常案件不抢注意力；首页优先“需要你决定 / Agent 正在处理 / 有风险 / 已完成”，每张人审卡只有一个主 CTA。
12. **Agent 运行可恢复**：Activity Rail 只展示当前工作、触发原因、版本输入、完成/等待步骤、当前等待对象、下次检查、最晚升级、Owner、暂停与恢复点，不展示思维链或 Prompt，不编造精确完成时间。
13. **高级但克制**：专业、安静、可信、精确；使用留白、排版、版本差异和语义状态，不使用霓虹、机器人头像、持续发光、AI 大脑动画或玻璃拟态堆叠。随包色值、间距与动效数值只是参考，不是冻结品牌或像素级验收条件。

## 6. 建议的信息架构

业务端主导航固定控制在六项以内，可优化命名但不能再增加画像治理一级入口：

1. **首页**：待决定、Agent 正在处理、风险和最近完成。
2. **招聘任务**：按岗位、负责人、阶段、时限和风险查看案件。
3. **面试**：待排期、已排期、面前简报、面后确认与多轮协同。
4. **终面评估**：已就绪、待补全和已失效的终面评估材料。
5. **异常与接管**：需要人处理的最小决策包与恢复入口。
6. **设置与治理**：动作权限、质量、审计、连接器和画像治理；仅授权管理角色可见。**画像治理必须是这里的授权子导航**，不能抢占普通招聘用户的一级导航。

候选人移动端协调页是独立安全链接，不占业务端主导航。角色无权访问的页面既要隐藏导航，也要在旧链接/深链访问时由服务端拒绝，不能只把按钮置灰。

不要把 `RuntimeEnvelope`、事件名、幂等键、hash 或内部聚合名称直接作为普通业务用户的主界面语言。它们可以出现在审计抽屉或运营详情中。

普通业务界面还必须把内部术语翻译为可理解的中文：显示“正在停止处理，请稍候”，不显示 `STOPPING`；显示“严重风险，相关操作已暂停”，不显示 `P0`；显示“分析样本与覆盖范围”，不显示 `Cohort`；显示“已暂停使用此版本”，不显示 `Freeze`；显示“仅做后台验证，不影响实际招聘”，不显示 `A0`。翻译后仍须保持“正在”与“已经”、提案与生效的真实差异。

## 7. 必须设计的关键界面

### A. 今日工作台 / 控制塔

- 可信托管完成趋势、在途案件、接近时限、计划外 HR 介入和严重/高风险；内部风险码不出现在普通首页。
- 按“需要我决定”“Agent 正在处理”“等待外部输入”“异常需接管”分区。
- 每张卡显示下一动作、原因、截止、案件与岗位，不用一大张密集状态表代替工作流。

### B. 申请案件详情

- 顶部：候选人、岗位、招聘周期、当前大阶段、Owner、SLA、暂停/接管。
- 主区：从投递到终面包的业务时间线，区分事实、材料、人工决定和外部动作回执。
- 侧区：当前待办、当前版本、风险、异常、数据/同意控制。
- 能从同一案件进入匹配材料、轮次、会话、评价和终面评估包，但不把页面拆成技术对象浏览器。

### C. 用人部门匹配审阅卡

- 岗位画像版本、必要条件、逐维证据、反证/信息不足、来源定位、Agent 置信提示。
- 人工动作：进入面试、拒绝、保留/稍后再看、请求补充；不预选任何决定。
- 低分不得自动关闭案件；拒绝沟通是决定之后的独立动作。

### D. 候选人协调页（移动优先）

- 展示候选人时区下的可选时段、面试轮次概述、参与人角色和预计时长。
- 支持选时段、改期、声明不可用、请求人工协助；并发失效时用友好方式刷新提案。
- 录制告知与选择必须显著、逐目的、可证明、可撤回；提供同等可用的无录制路线。
- 清楚区分采集模式（RECORDING / NO_RECORDING）和证据交接路线（RECORDED_EVIDENCE / AUTHORIZED_NOTES_ONLY）；后者失效时旧版本只读且不可继续使用。
- AUTHORIZED_NOTES_ONLY 只表示本次交接不引用音视频证据，不等于会议从未尝试或发生采集；原型必须展示真实采集历史、撤回后的片段处置与最终对账，并在 Session 未结束或采集未结算时禁用交接。
- 同一轮包含多个必需会话时，任一会话开始后 Round 即进入并保持 IN_PROGRESS；剩余会话仍可继续约面，后续 Booking 不能把 Round 回退成 SCHEDULED。

### E. 面试官面前简报

- 本轮目标、评分卡维度、未覆盖证据、待验证事实和建议问题。
- 每个问题说明对应维度/缺口；面试官可接受、编辑、忽略或举报问题。
- 独立评价前不展示前轮总分、推进决定和身份化意见。

### F. 面后证据与评价确认

- 纪要与证据化评价草稿并排或可顺畅切换；关键 claim 可回到源片段。
- 显示信息不足、说话人/转写置信问题、敏感内容隔离和版本差异。
- 面试官可修改、确认或退回；确认之后由有权限的人主动作轮次决定。

### G. 终面评估包

- 按评分卡维度汇总多轮支持证据、反证/差异、信息不足、证据复用、豁免和跨轮问题。
- 显示 Input Manifest 的业务化摘要、包版本、当前有效性和最终审阅任务。
- 不出现 Agent 的录用/淘汰建议、候选人排名或单一人格/能力总分。
- 输入变化时旧包显著失效、只读，并引导到当前版本；`终面评估就绪` 不等于已录用。

### H. 异常包与人工接管

- 标题、影响范围、事实、已尝试动作、风险、选项、建议、Owner、截止和恢复条件。
- 覆盖路由冲突、部门超时、无共同时间、日历部分成功、错误收件人、同意撤回、权限撤销和终面包失效。

### I. 运营 / 审计详情

- 动作级权限、频控、暂停、熔断和恢复；内部权限代码只在授权审计层出现。
- 可还原某次外发/决定当时读取的版本、权限和回执；默认不暴露原始敏感内容。

### J. 画像治理审阅（“设置与治理”下的授权子导航）

- 顶部显示 `当前 v4 → 候选 v5`、现在要决定什么、责任人、截止和唯一主要动作。
- 主区逐维展示画像差异、为什么建议、支持、反证、未知；不得用历史通过率冒充人才真值。
- 风险带展示完整分母、成熟/缺失/删失、置信区间、重要人群、公平/代理、用途与删除状态；业务 UI 称为“分析样本与覆盖范围”。
- 右侧展示只影响未来周期、在途案件不迁移、上一安全版本和人工回滚预览。
- 折叠层展示分析样本详情、预先登记的研究计划、Agent 动作/工具回执和最小化血缘；哈希、事件名与内部状态只进入授权审计抽屉。
- 需要作批准、要求修改或拒绝判断时，三个选项均不预选，唯一主按钮统一为中性的 **“提交你的决定”**；不能使用“批准并生效”“接受 AI 建议”等诱导文案。

#### J1. 角色 × 可见 × CTA × 禁止动作

| 角色 | 可以看到 | 唯一主要动作 | 明确禁止 |
|---|---|---|---|
| 用人负责人（Hiring Owner） | 版本差异、业务依据、反证/未知、未来范围、风险摘要 | 提交你的决定 | 改研究口径、看保护属性、单独发布、替另一角色会签 |
| HRBP / 画像治理负责人（Profile Governance） | 上述信息、治理规则、另一角色决定、未来范围、上一安全版本 | 提交你的决定 | 兼任同一提案的用人负责人、改结果标签、把共同批准冒充发布授权、直接发布/回滚 |
| 发布授权人（Publication Authorizer） | 双人批准事实、精确提案/资格/未来范围、计划生效时间、关键同步集、上一安全版本和回滚目标 | 提交你的决定 | 预授权/授权旧提案、从批准推导授权、替控制面准备或提交发布、由 Agent/Service 代签 |
| 结果数据管理员（Data Steward） | 来源冲突、阶段、成熟/缺失/删失、纠正血缘、处理队列 | 提交对账结果 | 评价候选人、批准提案、授权或发布画像、改招聘决定 |
| 隐私 / 公平负责人（Privacy/Fairness） | 用途、覆盖范围、重要人群伤害、代理风险、删除/限制状态 | 提交风险审查 | 把保护属性带入业务链、代业务批准或发布授权、直接改画像 |
| AI / 数据分析师（Analyst） | 固定分析样本与分区、候选生成清单、预登记口径、独立测试样本开启记录、指标/区间与因果边界 | 提交研究审查 | 看过独立测试结果后调候选、改变既定分区/口径、批准/授权/发布/回滚 |
| 招聘运营 | 当前生效版本、各下游回执、同步异常、等待对象、下次检查、最晚升级 | 提交接管方案 | 改观察/标签/研究/提案、补签批准、绕过当前版本 |
| Agent / 自动化服务 | 完成准备工作所需的最小版本化输入和回执 | 无业务决定按钮 | 确认真值、选择提案、批准、授权、发布、恢复使用或回滚 |

#### J2. Agent、提案、发布三类状态

三类状态必须由三个独立对象投影，不能做成一条含糊的“AI 进度”：

| 对象 | 普通界面状态示例 | 禁止冒充 |
|---|---|---|
| Agent 工作 | 正在收集、等待数据、等待人处理、已受阻、准备工作已完成 | 准备完成不等于形成提案、获批或生效 |
| 画像提案 | 草稿、待两方分别决定、要求修改、已拒绝、双人已批准、待发布授权、已失效 | 双人已批准不等于已经授权、创建版本、发布或同步 |
| 发布授权、发布与同步 | 发布授权任务待处理、已拒绝授权、已获当前授权等待准备、发布准备中、发布记录已创建等待同步、同步未完成、已生效、已暂停使用、已回滚 | 批准不等于授权；授权不等于控制面已准备、已提交或所有下游已生效 |

双人批准后必须先新建独立发布授权人任务；只有具备当前发布权限的 HUMAN 对精确提案、资格、未来范围、计划生效时间和回滚目标另行提交决定，才显示“已获当前授权，等待发布准备”。授权人可以与一名批准人是同一自然人，但必须使用独立发布权限、独立任务和独立签名，不能从批准记录推导。

发布与同步随后按两阶段展示：第一阶段由确定性控制面重验当前授权、基础版本、用途、未来范围与上一安全版本，创建不可变发布记录后只显示“发布记录已创建，等待同步”；第二阶段逐一核对当前版本指针和所有必需下游回执，全部一致才显示“已生效（仅未来招聘）”。部分失败显示“同步未完成”，逐系统说明实际版本、等待对象、下次检查与最晚升级；不得用绿色总状态覆盖差异。状态词典必须固定表达：**批准不等于授权，授权不等于发布准备，发布准备不等于生效**。

## 8. 必须可点击演示的流程

### 招聘中段正常链

新简历到达 → 自动解析/唯一路由 → 匹配材料就绪 → 用人负责人决定进入面试 → 候选人选时段 → 日历/会议预定成功 → 面试官收到面前简报 → 面试结束 → 评价草稿 → 面试官确认 → 人工轮次决定 → 多轮串联 → 当前终面评估包就绪。

### 招聘中段基础危险覆盖

这些状态仍须在对应页面走通，但不要与下面的 G3 八分支混号：

- 人或岗位路由不唯一：不得开“半个案件”，形成路由异常包。
- 用人部门打开旧匹配卡：旧版本只读，不能提交当前决定。
- 候选人选择时段后日历冲突：旧提案失效，不能重复建会或双重邀请。
- 候选人拒绝/撤回录制，或晚加入者未选择：立即请求停止采集并隔离新处理；平台未确认前显示“正在停止采集，相关处理已暂停”，不能乐观显示“已停止”，同时不取消面试机会。
- 案件暂停、候选人撤回或带作用域删除/限制生效：只在明确范围内优先停止待执行动作；迟到回调不得复活案件，也不得误伤范围外岗位。
- 面试证据交接被接收后，资产/笔记、同意、用途或控制失效：旧交接显著失效，不再读取/使用，迟到确认不复活它。
- 终面包就绪后某轮评价被修订：旧包和旧任务失效，案件回到待补全并产生新版本。

### G3 画像治理正常链

批准来源进入 → 结果观察与修订对账 → 成熟/资格判断 → 固定完整分析样本与分区 → **先冻结研究计划和候选修订，再打开独立测试样本** → 当前版与候选版离线比较 → 形成可审提案 → 两名不同职责的人分别提交批准决定 → 独立发布授权人提交当前 HUMAN 授权 → 确定性控制面发布准备（仅未来招聘）→ 必需下游同步与对账 → 确定性控制面提交当前版本指针并确认生效 → 按真实未来使用情况监控。

任一门不通过时只等待、拒绝或形成异常包，不自动改画像、调权、排名或迁移在途案件。

### G3 必须可点击的八个危险分支

1. **结果尚未成熟、来源冲突或后来更正**：保持未知/等待或交给结果数据管理员，不把缺失当失败；更正使所有旧派生物和旧任务失效。
2. **历史决定或仅录用者样本被当作真值**：显示完整分母和选择机制，阻断“旧画像选择谁 → 只有被选择者产生结果 → 再证明旧画像正确”的反馈环，不把旧拒绝/录用或幸存者结果外推为候选人能力及全漏斗因果结论。
3. **评测口径、分区或重要人群伤害不可信**：候选修订未先锁定、偷看测试样本、小样本/宽区间、同人穿透分区或重要人群退化时，只显示证据不足，不生成可发布提案。
4. **保护属性、代理变量或权利行为进入业务链**：隔离并阻断；姓名、学校、口音、邮编以及录制选择、辅助需求、申诉、删除请求等不得影响画像或招聘结果。
5. **跨岗位、跨租户或不可比分组合并**：无可比证据的跨岗合并被拒绝；跨租户混用立即暂停相关业务效果、定界和处置。
6. **删除、限制或用途失权后的全链召回**：停止读取和使用，结果标签、分析样本、评测、提案、导出与看板按血缘失效并给出回执；checkpoint 不得保留、恢复或重建正文。
7. **Agent 越权、同人兼签、缺失/旧授权任务或重复提交**：没有新版本或业务效果；旧批准/授权任务只读，两个不同职责的人分别提交当前批准决定后，仍需当前发布授权人完成独立任务；批准不能推导授权，Agent、Service 或控制面不能代签。
8. **发布/同步部分失败与暂停使用/人工回滚竞态**：逐系统显示实际状态；暂停使用优先，删除/限制等权利补偿继续，在途案件不迁移，人工只能回到此前批准且仍允许的版本。

## 9. 明确禁止的设计

- 不让 Agent 自动提交邀请/拒绝、轮次决定、录用或淘汰。
- 不用一个“AI 综合分”支配页面层级或候选人排序。
- 不把密集表格、日志、状态枚举或工程事件流当成普通用户的主要体验。
- 不要求 HR 点击“开始”才能接收、解析或正常推进案件。
- 不把会议邀请中的录制条款当成参与人有效同意。
- 不把“同意录制”设计成默认勾选或拒绝后体验降级。
- 不在独立评价前向面试官泄露前轮总分、结论或推进决定。
- 不让通知、邮件或 IM 卡片成为唯一权威状态源；产品内任务才是权威入口。
- 不隐藏信息不足、跨轮差异、证据复用、豁免和旧版本失效。

## 11. 原型验收标准

- 新用户在 30 秒内知道“系统正在做什么、现在谁需要做什么、截止何时”。
- 正常案件无需 HR 手动点火；必要人类决定清楚、低摩擦、不可被 Agent 越过。
- 任一关键评价可回到可定位证据；信息不足不会被表现成负面判断。
- 候选人拒绝录制仍能完成同等面试流程。
- 旧版本、迟到回调和重复点击不会在界面上表现成第二个当前事实。
- 最终决策人能区分“终面材料已就绪”和“最终招聘决定已作出”。
- 视觉应是可信、克制、现代的企业级产品，不是 AI 炫技面板，也不是 ATS 数据表翻版。
- 用人负责人（Hiring Owner）、HRBP / 画像治理负责人（Profile Governance）、发布授权人（Publication Authorizer）、结果数据管理员（Data Steward）、隐私 / 公平负责人（Privacy/Fairness）、AI / 数据分析师（Analyst）和招聘运营七类 G3 HUMAN 分别完成关键任务时，能区分 Agent 准备完成、画像提案双人批准、独立发布授权、控制面发布准备、发布记录创建、下游同步和当前生效；关键误解为 0。
- 无权角色看不到治理入口，使用旧链接或深链也不能完成禁止动作；拒绝、要求修改、暂停、接管和恢复与批准同样可达。
- 超时、刷新、重复提交、部分同步和接管后都能从权威事实恢复；Activity Rail 能回答等待谁、何时再查、最晚何时升级。
- 键盘、读屏、焦点、200% 缩放重排、非颜色状态、长文本、时区/语言和 reduced motion 走通，目标达到适用的 WCAG 2.2 AA。
- “画面好看”或设计 Token 一致不能单独通过验收；必须同时提供任务成功/关键误解、恢复演练和无障碍证据。
